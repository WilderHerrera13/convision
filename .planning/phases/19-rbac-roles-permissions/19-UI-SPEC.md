### 5. AuthContext Permission Methods

New methods added to `AuthContextType`:

```typescript
hasPermission(permission: string): boolean
hasAnyPermission(...permissions: string[]): boolean
hasAllPermissions(...permissions: string[]): boolean
```

**Implementation:**
- `permissions` is stored in the `User` object (from localStorage, populated by login/me response)
- `hasPermission` does `permissionsSet.has(permission)` — convert array to `Set<string>` on user load for O(1) lookup
- `hasAnyPermission` does `permissions.some(p => permissionsSet.has(p))`
- `hasAllPermissions` does `permissions.every(p => permissionsSet.has(p))`
- All three are stable references (wrapped in `useCallback` with `[permissions]` dependency)

**Backward compat methods (deprecated, kept for transition):**
```typescript
isAdmin(): boolean → hasPermission('roles_permissions:manage')
isSpecialist(): boolean → hasAnyPermission('appointments:view', 'prescriptions:create')
isReceptionist(): boolean → hasAnyPermission('patients:view', 'sales:create')
```

### 6. Refactored Role Checks Across the App

Replace ALL instances of:
- `user.role === 'admin'` → `hasPermission('roles_permissions:manage')` or specific permission
- `user?.role === 'admin'` → same pattern with null-safe `hasPermission` call
- `isAdmin()` → kept during transition, internally delegates to `hasPermission`
- `allowedRoles={['admin']}` in route wrappers → `requiredPermission="users:view"` or equivalent

**Refactoring map (from CONTEXT.md §7.4):**
~30 files with ~50+ checks. Each file must be audited individually during implementation.

The `role_type` field is preserved ONLY for theming purposes:
- `AdminLayout` sidebar role-based styling
- Dashboard welcome banner color
- Any component that renders role-specific visual treatment (colors, icons)

## Interaction Patterns

### RolesManagementPage

1. **Page load:** EntityTable fetches page 1 with per_page=15. Shows skeleton loading state.
2. **Search:** Typing in the search bar triggers API request with debounce (EntityTable built-in, 300ms). URL query params: `s_f=["name"]&s_v=["<search>"]`.
3. **Create role:** "Crear Rol" button → Dialog opens → Fill form → "Guardar Cambios" → POST /api/v1/roles → on success: close dialog, refetch table, show toast.
4. **Edit role:** Click pencil icon → Dialog opens pre-filled with role data + permission checkboxes pre-checked → Edit → "Guardar Cambios" → PUT /api/v1/roles/:id → on success: close dialog, refetch table, show toast.
5. **Delete role:** Click trash icon → Confirmation dialog → "Eliminar Rol" → DELETE /api/v1/roles/:id → on success: close dialog, refetch table, show toast.
6. **System role guard:** Delete button disabled, tooltip shown on hover. Backend returns 403 for forbidden deletes (belt and suspenders).
7. **Accordion interaction:** Click module header to expand/collapse. "Seleccionar todos" / "Deseleccionar todos" toggles check/uncheck all actions in that module.
8. **Row click:** No row click action — table is not clickable. All actions via explicit buttons.

### User Role Assignment

1. **View current roles:** Badges visible on page load. Data from `GET /api/v1/users/:id/roles`.
2. **Remove role:** Click X on badge → DELETE /api/v1/users/:id/roles/:roleId → on success: remove badge, recalculate effective permissions.
3. **Add role:** Click "Agregar Rol"→ SearchableCombobox appears with available roles → type to filter → select role → POST /api/v1/users/:id/roles (body: {role_id}) → on success: add badge, recalculate effective permissions.
4. **Effective permissions update:** Recalculated client-side on every role add/remove. Computed as union of all `permissions` arrays from assigned roles.

### Permission Matrices

1. **Accordion default state:** All collapsed on dialog open (Create mode). For Edit mode, accordions with checked permissions start expanded; empty ones collapsed.
2. **"Seleccionar todos" behavior:** When clicked, checks all action checkboxes in that module. Text changes to "Deseleccionar todos" (bold). When any individual checkbox is unchecked, the "todos" label reverts to "Seleccionar todos" (regular weight).
3. **Module badge counter:** Updates in real-time as checkboxes are toggled. Shows `"{checked}/{total}"` — e.g., "3/4" for 3 checked out of 4 actions. Green text when all checked, blue otherwise.
4. **Scroll area:** Permission matrix wrapped in `ScrollArea` with `max-h-[400px]` to prevent dialog from exceeding viewport height. Inner content fills available space.

### Form Validation Feedback

1. **Inline validation** (react-hook-form + zod):
   - Name required: red border on Input + "El nombre del rol es obligatorio." below (text-error, text-xs, mt-1)
   - Name duplicate: checked on blur via async validation (debounced 500ms). Shows "Ya existe un rol con ese nombre." below the input.
   - No permissions: red text below permissions section heading: "Debe seleccionar al menos un permiso."
2. **Server errors:**
   - 409 Conflict (duplicate name): "Ya existe un rol con ese nombre." toast (error variant)
   - 403 Forbidden (system role delete): "No se pueden eliminar roles del sistema." toast (error variant)
   - 500/network error: "Error al guardar el rol. Intente nuevamente." toast (error variant)

### Loading States

1. **Roles table:** 5 skeleton rows while loading (shadcn `<Skeleton>` in table cells, matching column widths).
2. **Permission matrix (edit mode):** Skeleton blocks replacing the accordion while permissions data loads.
3. **Save button:** Shows spinner + "Guardando..." text while API call is in flight. Button disabled to prevent double-submit.
4. **Delete button:** Shows spinner + "Eliminando..." while API call is in flight. Dialog stays open until success/error.

### Error States

1. **Roles table fails to load:** EntityTable shows error message: "Error al cargar los datos. Intente nuevamente." with a retry button.
2. **Permission data fails to load (edit mode):** Error message in dialog body: "No se pudieron cargar los permisos. Cierre e intente de nuevo."
3. **Save fails (network):** Toast "Error al guardar el rol. Intente nuevamente." Dialog stays open so user doesn't lose form data.
4. **Delete fails:** Toast "Error al eliminar el rol. Intente nuevamente." Confirmation dialog closes (action already attempted).

## Responsive Behavior

Follows Phase 15 patterns. Key responsive breakpoints:

1. **RolesManagementPage:** Full width on all screens. EntityTable adapts naturally.
2. **Create/Edit Role dialog:** `max-w-2xl` on desktop, `max-w-[calc(100vw-2rem)]` on mobile (via dialog component). ScrollArea height reduces to `max-h-[300px]` on screens below `sm:`.
3. **Permission matrix checkboxes:** `grid-cols-3` on `md:`, `grid-cols-2` on `sm:`, `grid-cols-1` below `sm:`.
4. **User role badges:** `flex-wrap` naturally stacks on narrow screens.

## Accessibility

1. **Dialog focus trap:** shadcn Dialog handles focus management — focus returns to trigger element on close.
2. **Accordion ARIA:** shadcn Accordion provides `aria-expanded`, `aria-controls`, keyboard navigation (Enter/Space to toggle).
3. **Checkbox labels:** All checkboxes associated with labels via `htmlFor`/`id` pairing — clickable label area.
4. **Edit button:** `aria-label="Editar rol {name}"` for screen readers.
5. **Delete button:** `aria-label="Eliminar rol {name}"` for screen readers.
6. **System role badge:** `aria-label="Rol del sistema, no se puede eliminar"` on the disabled delete button.
7. **Toast announcements:** shadcn Sonner toasts with `role="alert"` and `aria-live="polite"`.
8. **Loading states:** `aria-busy="true"` on loading containers.
9. **Keyboard flow:** Tab order: Name → Description → Permission accordions (Tab through accordion triggers, Enter to expand, Tab into checkboxes) → Cancel → Save. Natural Tab order for EntityTable: search → table rows → pagination.
10. **Color contrast:** All text meets WCAG AA (4.5:1 for normal text, 3:1 for large text). `convision-text` (#121215) on `convision-background` (#f5f5f6) = 17.1:1. Error text (#b82626) on white = 5.3:1.
