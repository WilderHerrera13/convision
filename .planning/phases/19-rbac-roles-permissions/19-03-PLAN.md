# Plan 19-03: Routes Migration — Replace ALL RequireRole with RequirePermission in routes.go

## Objective

Replace every `jwtauth.RequireRole(domain.RoleX, ...)` call in `routes.go` with the equivalent `jwtauth.RequirePermission("...")` or `jwtauth.RequireAnyPermission("...", "...")`. After this phase, all route access control is permission-based. `RequireRole` middleware is kept for compatibility during transition but no longer used in routes.go. All 180+ calls must be replaced. The mapping follows the PRD Section 5.7 route-by-route table.

## must_haves

- [ ] All `RequireRole(domain.RoleAdmin, ...)` calls replaced with `RequireAnyPermission(...)` or `RequirePermission(...)` matching the user-to-permission mapping
- [ ] Admin-only routes use `RequirePermission("module:manage")` or specific permission where applicable
- [ ] Mixed-role routes use `RequireAnyPermission` with the specific permissions each role has
- [ ] Super-admin routes use `RequirePermission` (super-admin JWT will have all permissions set)
- [ ] No route left behind — every `RequireRole` call site in routes.go is replaced
- [ ] `RequireRole` middleware kept in codebase but not referenced in routes.go
- [ ] `make build` exits 0

<action>
After routes migration, verify that the permission system works correctly. Run these curl tests against the running backend after seeding is complete:

```bash
# 1. Login as admin (should get permissions in JWT)
TOKEN=$(curl -s --location 'http://localhost:8001/api/v1/auth/login' \
  --header 'Content-Type: application/json' \
  --data-raw '{"email":"admin@convision.com","password":"password"}' \
  | jq -r '.access_token')

# 2. Verify admin can access patients list (has patients:view)
curl -s http://localhost:8001/api/v1/patients -H "Authorization: Bearer $TOKEN" | jq '.status // "200 OK"'

# 3. Verify admin can access admin-only routes (has branches:manage)
curl -s http://localhost:8001/api/v1/branches -H "Authorization: Bearer $TOKEN" | jq '.status // "200 OK"'

# 4. Login as specialist
SPEC_TOKEN=$(curl -s --location 'http://localhost:8001/api/v1/auth/login' \
  --header 'Content-Type: application/json' \
  --data-raw '{"email":"specialist@convision.com","password":"password"}' \
  | jq -r '.access_token')

# 5. Specialist can access appointments (has appointments:view)
curl -s http://localhost:8001/api/v1/appointments -H "Authorization: Bearer $SPEC_TOKEN" -H "X-Branch-ID: 1" | jq '.status // "200 OK"'

# 6. Specialist CANNOT access branches (missing branches:manage)
curl -s http://localhost:8001/api/v1/branches -H "Authorization: Bearer $SPEC_TOKEN" | jq '.message'
# Expected: "forbidden: insufficient permissions"
```

Key scenarios to verify:
- Admin: can access ALL endpoints → 200
- Specialist: can access appointments, prescriptions, clinical → 200; cannot access users, branches, bulk-import → 403
- Receptionist: can access patients CRUD, sales, quotes → 200; cannot access users, branches → 403
- Laboratory: can access laboratory-orders status → 200; cannot access patients CRUD → 403
- Unauthenticated: all protected routes → 401
</action>
