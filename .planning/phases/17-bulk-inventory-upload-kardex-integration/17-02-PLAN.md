## Objective

Add "Inventario" as a new import type in the bulk import module. This involves:
1. Adding the option card in the type-selection page
2. Adding the config and result display for inventory import in the main BulkImportPage
3. Adding the `uploadInventory` API call to the service
4. Registering the route in App.tsx

## Context

### Existing architecture
- `ImportTypeSelectPage.tsx` — grid of `OPTIONS` cards, each with `type`, `path`, `columns`, `icon`
- `BulkImportPage.tsx` — single page for all import types, driven by `config` const (TypeConfig per type)
  - `importType` derived from URL `type` param
  - `config` selected by `importType` switch
  - `handleProcess` calls the right service method
  - `ResultTable` uses `dataKeys` array (keyed on normalized column names)
  - `StatusBadge` renders `created` / `skipped` / `error` — needs `updated` badge added
- `bulkImportService.ts` — `ImportType` union type, one method per type
- `App.tsx` — route `/admin/bulk-import/:type` already renders `<BulkImportPage />`

### Excel columns (from `Inventario.xlsx`)
`Código, Identificador, Descripción, tipoproducto, Marca, Categoria, Tipo, Cant, precioventa, preciocompra, Sede`

### Backend response for `updated` status
The backend returns `status: "updated"` (new `RecordStatus`) for rows where stock was added to an existing inventory item (vs `"created"` for new products/items, `"error"` for failures). The frontend must render this distinctly.
