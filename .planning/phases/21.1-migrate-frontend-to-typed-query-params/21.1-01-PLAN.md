# Plan 21.1-01: Migrate list-page services and direct page callers to typed flat query params

## Objective

Cut over the patient and appointment list-page surface (services + the pages that call axios directly) from the legacy `s_f`/`s_v`/`s_o=or` JSON-array contract to flat `?key=value` query params that bind 1:1 to the Go `domain.<Entity>Filter` struct form tags introduced in Phase 21. Includes the in-page direct API calls in `pages/{admin,receptionist}/Patients.tsx`, `pages/admin/Appointments.tsx`, `pages/receptionist/NewQuote.tsx`, and `components/discounts/DiscountRequestModal.tsx` because they bypass the service layer and emit the legacy params themselves. After this plan: zero `s_f`/`s_v`/`s_o` references in the listed files.

<threat_model>

Trust boundary: React client → Go API. The migration only changes the request URL shape; the auth/authorization/branch-isolation surface is unchanged.

- **T-21.1-01-01 Tampering (request shape):** A malicious client could attempt to bypass server-side validation by sending unexpected query keys.
  - *Mitigation (existing):* backend re-validates every request via `c.ShouldBindQuery(&filter)` against the typed Filter struct; unknown keys are silently dropped, no privilege escalation possible.
- **T-21.1-01-02 Information Disclosure (branch leakage):** If FE accidentally emits `branch_id` as a query param, a user with multi-branch access could leak data across branches.
  - *Mitigation (D-13):* this plan removes any `branch_id` from query params on the migrated surfaces; the X-Branch-ID header set by the existing axios interceptor (`src/lib/axios.ts`) remains the only branch source. Verified by `grep` in T5.
- **T-21.1-01-03 Spoofing:** Out of scope — auth/JWT flow unchanged.

</threat_model>
