# Phase 21.1 Plan 01: Migrate list-page services and direct page callers Summary

**Cut over patient/appointment/clinical evolution services and 8 page-level callsites from legacy s_f/s_v/s_o JSON-array contract to flat ?key=value params matching Go domain Filter struct form tags.**

## Performance

- **Duration:** ~15min
- **Started:** 2026-05-09
- **Completed:** 2026-05-09
- **Tasks:** 5
- **Files modified:** 9

## Accomplishments

- **patientService:** `PatientFilter` interface added (mirroring domain.PatientFilter: page, per_page, search, status, gender). `searchPatients` now emits flat `search` — the 4-column OR-ILIKE fan-out happens server-side per Phase 21-08. `PatientSearchParams` kept as alias for backward-compat with `perPage` callers.
- **appointmentsService:** `AppointmentFilter` interface added (status, specialist_id, patient_id, taken_by_id, consultation_type, start_date, end_date, patient_search, attended_by, pending_report). `getAppointments` maps known legacy keys directly to typed form-tag names. `searchPatients` uses flat `search`. `branch_id` query param removed (D-13 — X-Branch-ID header is canonical).
- **clinicalEvolutionService:** `params.appointment_id = appointmentId` replaces the `s_f`/`s_v` JSON-array construction. Backend handler doesn't read `appointment_id` yet (will be flagged in 21.1-03 audit per D-11).
- **Page callers (8 sites in 5 files):** admin/Patients, receptionist/Patients, admin/Appointments, NewQuote (2 sites), DiscountRequestModal (2 sites) — all `s_f`/`s_v`/`s_o` construction replaced with flat `search` or `role_type` keys.
