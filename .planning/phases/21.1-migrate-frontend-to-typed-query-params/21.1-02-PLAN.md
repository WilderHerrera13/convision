# Plan 21.1-02: Migrate catalog and dropdown services to typed flat query params

## Objective

Cut over the catalog / inventory / dropdown surface (lens, catalog, inventory, brand, category, supplier, laboratory, user services) from the legacy `s_f`/`s_v` JSON-array contract to flat `?key=value` query params matching the Go `domain.<Entity>Filter` struct form tags. Preserves the documented userService `branch_id` alias exception (Phase 21-10). Direct cut-over per D-07.

<threat_model>

Trust boundary: React client → Go API. Request-shape change only.

- **T-21.1-02-01 Tampering:** Same as 21.1-01 — backend re-validates via `ShouldBindQuery`; unknown keys dropped.
- **T-21.1-02-02 Information Disclosure (cross-branch leakage in inventory/lens lookups):** inventory items, warehouses, and lens stock are branch-scoped; emitting a forged `branch_id` would not bypass auth (server uses X-Branch-ID header per D-13) but COULD be misread as a filter value. *Mitigation:* this plan removes all `branch_id` query param emissions EXCEPT the userService legacy alias (Phase 21-10) and the inventoryService `allBranches` flag where branch_id=0 is a documented "all branches" sentinel for super-admin views.
- **T-21.1-02-03 Information Disclosure (lens catalog by prescription):** the per-eye prescription floats are user-supplied refraction values; backend rejects non-floats. *Mitigation (existing):* `*float64` form-tagged binding fails with HTTP 400 on malformed input.
- **T-21.1-02-04 Spoofing:** Out of scope — auth unchanged.

</threat_model>

## Risks & Rollback

- **Risk:** Some catalog endpoints (`/api/v1/brands`, `/api/v1/lens-classes`, `/api/v1/treatments`, `/api/v1/categories`) may not have typed Filter structs yet on the backend, so the new flat `search` / `name` key is silently ignored and the dropdown returns ALL records. *Mitigation:* the dropdowns historically returned full lists anyway (the s_f/s_v acted as client-side hints for tiny tables); functional impact is negligible. Surface every gap in 21.1-03 audit (D-11) for backend follow-up.
- **Risk:** The lens catalog's removed `lensAttributes.material_id` / `lens_class_id` / `treatment_id` JOIN filters break the lens-search UI. *Mitigation:* if the UI needs these filters, document the backend gap in 21.1-03 — `LensCatalogFilter` does not currently expose them and the FE cannot fake them via legacy s_f after this plan.
- **Risk:** userService branch_id alias regression breaks ListByBranch routing. *Mitigation:* T4 explicit comment + verification HAR for users-list-by-branch.
- **Rollback (D-09):** revert the single phase commit; legacy keys re-enabled instantly.
