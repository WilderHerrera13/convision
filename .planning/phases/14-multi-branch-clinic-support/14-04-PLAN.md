## Context

All "local" data (appointments, sales, cash closes, daily reports, inventory) must be filtered by `branch_id` drawn from the Gin context (set by the BranchContext middleware in wave 2). This plan updates each entity's service, repository, and handler layer. The pattern is identical for each entity:

1. Service `CreateInput` / `ListInput` (or filters map) gains `BranchID uint`
2. Repository `List` gains `WHERE branch_id = ?` predicate; `Create` sets `branch_id`
3. Handler calls `branchmw.BranchIDFromCtx(c)` and passes it through

The clinical record handlers use `branchID` (formerly `clinicID`) — those references must be updated to call `BranchIDFromCtx` instead of whatever hardcoded value was used before.

3. In `CreateAppointment` handler, after binding the input:

4. Repeat for all other write handlers (UpdateAppointment, TakeAppointment, etc.) — the branch_id from ctx is the authority; do not trust a client-sent branch_id.
