## Context

This plan creates all DB schema changes needed for multi-branch support. The existing `clinic_id` column on inventory/clinical tables is an orphan reference; it must be renamed to `branch_id` with a real FK. Four tables (appointments, sales, cash_register_closes, daily_activity_reports) have no branch association today and need a new `branch_id NOT NULL` column. The migration order is critical: create `branches` first, seed a default branch, backfill, then add constraints.

Dev environment only — DB wipe is acceptable. No backward-compat needed.

    address    VARCHAR(255),
    city       VARCHAR(100),
    phone      VARCHAR(30),
    email      VARCHAR(150),
    is_active  BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 2. Trigger: auto-update updated_at on branches
CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$;

DO $$
BEGIN
    IF NOT EXISTS (
        SELECT 1 FROM pg_trigger
        WHERE tgname = 'trg_branches_set_updated_at'
          AND tgrelid = 'branches'::regclass
    ) THEN
        CREATE TRIGGER trg_branches_set_updated_at
        BEFORE UPDATE ON branches
        FOR EACH ROW EXECUTE FUNCTION set_updated_at();
    END IF;
END;
$$;
