## Hallazgos (FAIL / GAP)

### QA-001

- **Rol:** admin (todos los roles)
- **URL:** `POST http://localhost:8001/api/v1/bulk-import/inventory` (afecta todos los sub-endpoints `/bulk-import/*`)
- **Severidad:** menor (pre-existente, no introducido por fase 17)
- **Pasos:**
  1. Llamar a cualquier endpoint `/api/v1/bulk-import/*` autenticado como admin.
  2. Omitir completamente el campo `file` (no enviar multipart body válido).
- **Esperado:** HTTP 400 `"Se requiere el campo 'file' con el archivo Excel"`.
- **Observado:** HTTP 413 `"El archivo supera el límite de 10 MB"`.
- **Evidencia:**
  ```
  curl -s -X POST http://localhost:8001/api/v1/bulk-import/inventory \
    -H "Authorization: Bearer $TOKEN" \
    -H "Content-Type: multipart/form-data"
  → HTTP 413 {"message":"El archivo supera el límite de 10 MB"}
  ```
- **Causa raíz:** en `processBulkImport`, `c.Request.ParseMultipartForm(maxUploadSize)` falla para cualquier body inválido (vacío, no-multipart) y el error se mapea al catch genérico de "archivo supera límite". El `c.FormFile("file")` (que retorna 400 correcto) nunca se alcanza.
- **Estado:** confirmado
- **Aplica a:** todos los endpoints `/bulk-import/*` (patients, doctors, lenses, staff-users, inventory)
- **Fix sugerido:** verificar si `err` de `ParseMultipartForm` es `http.ErrMissingBoundary` o cuerpo vacío antes de retornar 413.

### QA-003 — [CORREGIDO EN SESIÓN, documentar en guía]

- **Rol:** n/a (setup de entorno local fresco)
- **Severidad:** mayor (bloquea `make dev` en instalación limpia)
- **Pasos:**
  1. DB recién creada sin schema `optica_main`.
  2. Ejecutar `APP_ENV=local ./bin/convision-api`.
- **Esperado:** `MigrateTenantSchema` crea el schema.
- **Observado:** fatal:
  ```
  ERROR: no schema has been selected to create in (SQLSTATE 3F000)
  ```
- **Causa raíz:** `MigrateTenantSchema` hace `SET search_path = optica_main` pero PostgreSQL requiere que el schema exista previamente para crear tablas en él. `optica_main` no existía.
- **Fix aplicado:** `CREATE SCHEMA optica_main` + `INSERT INTO platform.opticas` antes de arrancar el servidor.
- **Estado:** confirmado → workaround documentado. El script `start.sh` o `DEVELOPMENT_GUIDE.md` debería incluir `CREATE SCHEMA IF NOT EXISTS optica_main` como paso de onboarding.

### QA-004 — [CORREGIDO EN SESIÓN]

- **Rol:** n/a (infraestructura DB existente)
- **Severidad:** mayor en entornos que migraron de GORM más antiguo
- **Descripción:** AutoMigrate falló en `platform.opticas` y `platform.super_admins` porque las constraints se crearon con nombres de formato antiguo (`opticas_slug_key`, `opticas_schema_name_key`, `super_admins_email_key`) mientras GORM espera `uni_opticas_slug`, `uni_opticas_schema_name`, `uni_super_admins_email`.
- **Fix aplicado:**
  ```sql
  ALTER TABLE platform.opticas RENAME CONSTRAINT opticas_slug_key TO uni_opticas_slug;
  ALTER TABLE platform.super_admins RENAME CONSTRAINT super_admins_email_key TO uni_super_admins_email;
  ```
- **Estado:** confirmado → corregido en DB de desarrollo.
