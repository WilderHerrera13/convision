## Hallazgos (FAIL / GAP)

### QA-001 — Sales filter modal crashes on open

- **Rol:** admin
- **URL:** http://localhost:4303/admin/sales
- **Severidad:** bloqueante
- **Pasos:**
  1. Login as admin
  2. Navigate to Ventas page
  3. Click "Filtrar" button to open filter modal
- **Esperado:** Filter modal opens showing branch filter, status, payment status, date range, patient ID
- **Observado:** "Unexpected Application Error!" — crashes with: `A <Select.Item /> must have a value prop that is not an empty string. This is because the Select value can be set to an empty string to clear the selection and show the placeholder.`
- **Evidencia:** Browser rendered error boundary with full stack trace visible
- **Causa probable:** Sales.tsx filter modal uses `<SelectItem value="">` (empty string) in shadcn Select components, which is not allowed in newer shadcn/ui. Status filter (line 662) and Payment Status filter (line 680) both use `value=""`.
- **Estado:** confirmado

### QA-002 — Admin Appointments page missing branch filter

- **Rol:** admin

### QA-003 — Admin forced to select a branch at login

- **Rol:** admin
- **URL:** http://localhost:4303/select-branch (after login redirect)
- **Severidad:** mayor
- **Pasos:**
  1. Login as admin
  2. Observe that user is redirected to /select-branch
  3. Must pick one specific branch (Principal, Sede Centro, Sede Norte, or Sede Sur)
- **Esperado:** The requirement states: "el admin no debe seleccionar una sede en especifico al hacer login pues tiene el control sobre todas". Admin should bypass branch selection or have a "Todas las sedes" option at login.
- **Observado:** Admin is presented with 4 branch choices and MUST select one specific branch to proceed. The "Selecciona una sede" button is disabled until a specific branch is chosen. No "Todas las sedes" option.
- **Evidencia:** Snapshot shows branch selection page with 4 branch buttons (Principal, Sede Centro, Sede Norte, Sede Sur) and a disabled "Selecciona una sede" button. Admin must click one specific branch ("Continuar a Principal") to proceed.
- **Nota adicional:** After selecting a specific branch, the admin does see the branch filter in tables allowing them to filter by all branches — but the initial forced selection is semantically incorrect per requirements.
- **Estado:** confirmado

## Observaciones adicionales

1. **AdminBranchFilter component** (`AdminBranchFilter.tsx`) works correctly — uses `SearchableCombobox` per project rules, shows "Todas (N)" + individual branch names, auto-hides when branches ≤ 1.

2. **Backend API** returns 4 branches for admin: Principal (id:1), Sede Centro (id:3), Sede Norte (id:4), Sede Sur (id:2). The `branch_id` filter is properly passed to API queries (`GET /api/v1/cash-register-closes?branch_id=X`, etc.).

3. **RBAC correct:** Receptionist only sees assigned branches (2 of 4) and does not have AdminBranchFilter in their views.

4. **Backend handlers** that support `branch_id` filtering: `cash_register_close`, `laboratory_orders`, `daily_activity_reports`, `sales`. Confirmed from modified handler files.
