## Hallazgos (FAIL / GAP)

### QA-001 — Inventory page shows empty "Sin stock" — all inventory handlers use global DB instead of tenant-scoped DB

- **Rol:** admin
- **URL:** `http://localhost:4300/admin/inventory`
- **Severidad:** bloqueante
- **Pasos:**
  1. Login as admin@convision.com
  2. Navigate to /admin/inventory
  3. Observe tabs "Stock", "Almacenes", "Ubicaciones", "Transferencias"
  4. All tabs show empty state
- **Esperado:** Inventory items table populated with 6368 items (across 5 branches). Warehouses list populated.
- **Observado:** "Sin stock" and "Sin lentes en catalogo" empty states. Warehouses list empty. Direct SQL on `optica_main` schema returns correct data (6368 items, 5188 products, 12736 stock movements). The `ListProducts` endpoint works (uses `tenantDBFromCtx(c)` and passes db explicitly). Inventory handlers (`ListWarehouses`, `GetTotalStock`, `ListInventoryItems`, `ListLensCatalog`) do NOT call `tenantDBFromCtx(c)` — they use `h.inventory` service's internal `db` field set at construction time in `main.go` line 180: `inventorysvc.NewService(db, ...)` where `db` is the global connection WITHOUT `SET LOCAL search_path = optica_main`.
- **Root cause:**
  ```go
  // main.go line 180 — global db, no tenant schema set
  inventoryService := inventorysvc.NewService(db, warehouseRepo, ...)
  
  // handler_inventory.go line 35 — uses internal db (global, no schema)
  out, err := h.inventory.ListWarehouses(filters, page, perPage)
  
  // Compare with handler_product.go line 64 — uses tenant-scoped db
  db := tenantDBFromCtx(c)
  out, err := h.product.List(db, filters, page, perPage)
  ```
  All inventory handlers need to either pass `tenantDBFromCtx(c)` to their service methods, or the service must not rely on an internal DB field for read operations.
- **Fix:** Either (A) add `db := tenantDBFromCtx(c)` to all inventory handlers and pass `db` to service methods, or (B) make inventory service methods accept `db *gorm.DB` as first parameter. Pattern B is the approach used by `h.product.List(db, ...)`.
- **Evidencia:** Direct SQL confirms data exists (6368 items, 5188 products, 12736 movements). API returns empty (total=0). `handler_inventory.go:16-40` confirms missing `tenantDBFromCtx` call.
- **Estado:** confirmado

### QA-002 — Bulk import summary `created` counter includes `updated` records (misleading)

- **Rol:** admin
- **URL:** `POST http://localhost:8001/api/v1/bulk-import/inventory`
- **Severidad:** menor
- **Pasos:**
  1. Upload Inventario.xlsx via API (products already exist from prior run)
  2. Check API response summary vs individual row statuses
- **Esperado:** Summary counter reflects actual status distribution: `created: 0, updated: 6368, error: 0`
- **Observado:** Summary shows `created: 6368` while every individual row has `status: "updated"`. Caused by `RecordStatusUpdated` being mapped to `result.Created++` in `ProcessExcel` tally switch (17-01-PLAN.md Task 1 step 3).
  ```
  API response: {"created": 6368, "skipped": 0, "errors": 0}
  Individual rows: {"row": 2, "status": "updated", ...}
  ```
- **Fix:** Add separate `Updated` field to the `ImportResult` struct and its tally switch. Frontend `ResultSummary` component must display the updated count separately.
- **Evidencia:** `importer.go` RecordStatusUpdated, `service.go` ProcessExcel tally switch
- **Estado:** confirmado
